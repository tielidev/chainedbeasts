## Which enemy roles did the updated Demo preview name?

The June developer preview explicitly describes three roles: archers using range, wrestlers pinning gladiators until an ally rescues them, and defensive swordsmen attacking from behind shields. Those descriptions are more useful than treating every opponent as the same close-range target.

| Enemy role | Described behavior | Detail not supplied |
| --- | --- | --- |
| Archer | Attacks from range | Exact projectile speed, damage or a guaranteed dodge window |
| Wrestler | Pins a gladiator until a teammate rescues them | Universal solo escape input or exact rescue timing |
| Defensive swordsman | Attacks behind a shield | A complete weakness, guard-break or resistance table |

The source concerns the updated Demo. It does not identify every full-game enemy, every spawn or every version of these behaviors. Use the current game and version-labelled footage before turning a role description into a complete launch strategy.

## What should a party consider when ranged enemies are present?

Our recommendation is to include the ranged threat when choosing a route and avoid focusing only on the nearest enemy. Discuss where the group will move and whether the path creates a safe follow-up after an attack or throw.

This is positioning advice, not a claim that a particular object always blocks projectiles or that every attack can be interrupted. The [arena hazard guide](/combat/arena-hazards/) identifies environmental interactions the developer actually names. It should not be expanded into an undocumented cover system.

## How should you prepare for the described wrestler interaction?

The preview specifically mentions teammate rescue, so a cooperative group should pay attention when someone loses control of their position. Announce the problem and determine which ally can respond rather than continuing to pull the chain in a different direction.

The source does not explain the full solo case, the required input or a repeatable interrupt window. We do not supply those missing instructions from another game's mechanics. Use the [chain teamwork guide](/co-op/chain-teamwork/) for communication principles and check the current tutorial for actual actions.

## What does a shielded enemy description establish?

It establishes a defensive role. It does not prove an elemental weakness, a universal backstab bonus or a specific guard-break combo. When a tactic appears effective, identify the build, action and conditions before treating it as a rule for every shielded opponent.

Keep the player's shield system separate from an enemy's complete behavior. The [shield rework reference](/combat/shields-and-blocking/) documents historical player-equipment changes, but it is not a full enemy AI specification.
